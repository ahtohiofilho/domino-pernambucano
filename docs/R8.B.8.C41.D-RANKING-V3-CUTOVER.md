# R8.B.8.C41.D — Ranking V3 cutover

Status: **closed in source, pending release coordination**
Date: **2026-09-22**

## Scope

R8.B.8.C41.D completes the coordinated source-side activation of Ranking V3 and the compatibility boundary required before release.

Ranking V3 public order is:

1. **SV — Saldo de vitórias** — collective, higher is better.
2. **SP — Saldo de pontos** — collective, higher is better.
3. **PF — Pontos feitos** — individual, higher is better.
4. **AST — Assistências** — individual, higher is better.
5. **TQ — Toques dados** — individual, higher is better.
6. **ET — Estouro de tempo** — individual, lower is better.

SV and SP are shared by partners. PF, AST, TQ and ET are attributed to each player.

## ET semantics

A player receives at most **1 ET per round** when that player's own main clock expires and the player enters automatic mode.

The number of automatic plays that follow does not change the ET count. One, three or six automatic plays still represent a single ET for that player in that round.

The partner does **not** receive ET because of another player's timeout. Two different players can each receive 1 ET in the same round if both independently expire their own main clocks.

Normal server-controlled synthetic play does not create ET.

## Compatibility policy

V1 and V2 ranked results remain immutable and persisted.

There is no V2-to-V3 timeout backfill. Legacy data cannot reconstruct the exact number of historical timeout rounds, so V2 results are never rewritten as V3.

A ranked match freezes its ranking-rule version when it is created. A V1 or V2 match already in progress continues and finishes under its frozen version after the V3 cutover.

The current V3 ladder includes only results whose `rankingRuleVersion` is V3. Therefore V3 starts a fresh competitive epoch while historical V1/V2 data remains preserved and explicitly queryable.

Persistent server state schema is **14**.

## UI

The large always-visible ranking explanation card was removed.

The ranking screen keeps a compact always-visible context containing the cycle, participants, matches and publication/award status. Detailed ranking semantics are available on demand through **Como funciona?**

Historical/current V2 presentation continues to use **JA**. V3 presentation uses **ET**.

## Release coordination

C41.D changes source behavior only. It does not deploy production and does not publish a Play build.

Required release order for C41.E:

1. build and validate a V3-capable app in the Play internal track;
2. confirm client compatibility with the V3 public ranking contract;
3. only then deploy the V3-capable server/current-rule cutover;
4. perform physical end-to-end QA before consolidation.

Do not activate the V3 server against an installed client that predates V3 contract support.
